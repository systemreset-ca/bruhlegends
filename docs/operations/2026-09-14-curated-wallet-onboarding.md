# Curated private wallet onboarding

Owner-requested replacement for automatic first-contact generation. Private /start checks the authenticated Telegram account: a new account sees a curated welcome explaining the internal wallet, encrypted key handling, account-wide reuse, password setup and current devnet limitations. Generate BRUH Wallet is the explicit creation action. The existing private-only callback provisions/reuses the same encrypted wallet and edits that welcome message with its public address, Telegram Copy Address button, explorer link and direct private password Mini App button when the spending gates permit setup.

/security checks for an existing wallet; if none, it shows the same curated generation welcome rather than silently generating or issuing a broken password link. /wallet make uses that welcome too; /wallet show adds Copy Address. Existing /generate remains an explicit creation command. Returning /start reuses the existing wallet. Repeated callbacks cannot create a second active wallet due to the existing database provisioning rules. No keys enter messages; no funds move during onboarding. Passwords already enrolled cannot be overwritten by the setup screen. Private setup links remain single-use and expiring; /security refreshes a link.

Validation: onboarding tests cover read-only new start, same-message generation, exact copy text, private-only callback ownership, direct web_app setup button and blocked setup without a wallet. Public CI checks types/build/tests and revision integrity. Real Telegram client rendering remains an owner acceptance step. No website marketing, migrations, new providers, fees or network gates changed.
